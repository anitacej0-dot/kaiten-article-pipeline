# Навык: monthly-updates-source (разбор источника)

Первый этап ежемесячного обзора обновлений. Задача — превратить PDF в проверяемый
реестр фактуры, из которого потом пишется статья. Конвейер —
[`workflows/monthly_updates_pipeline.md`](../../workflows/monthly_updates_pipeline.md).

**Главное правило:** источник истины — только PDF. Внешний ресерч не нужен. Ничего не
додумываем: ни функций, ни цифр, ни тарифов, ни ссылок.

## Вход

- `articles/<папка>/00_intake.md` — путь к PDF, месяц, год, комментарии редактора.
- Сам PDF.
- `knowledge/monthly_updates_style_guide.md` — критерии деления на крупные и мелкие.
- Шаблон: `templates/monthly_updates_source_facts.md`.

## Что делать

### Шаг 1. Прогнать PDF через скрипт

```bash
python tools/pdf_extract.py --pdf "<путь к PDF>" --out "articles/<папка>" --render-pages
```

Скрипт создает `01_source_text.md`, раскладывает картинки в `assets/images/raw/`,
рендерит страницы в `assets/images/pages/` и пишет
`assets/images/extract_report.md` + `.json`.

Нет PyMuPDF — установить: `python -m pip install pymupdf`. Текст руками не набивать.

### Шаг 2. Прочитать выгрузку и отделить фактуру от шума

Читаем `01_source_text.md` целиком. В шум и **в реестр не идут**:

- служебное из рассылки: тема письма, прехедер, «Здравствуйте», подписи, ссылки на регистрацию;
- анонсы вебинаров, промо-баннеры и приглашения на эфиры — это не обновления продукта;
- **строки-эхо** из раздела «Шум PDF»: alt-текст непрогрузившейся картинки, который
  дублирует заголовок над ней;
- колонтитулы, номера страниц, адреса документа.

### Шаг 3. Собрать полный список обновлений

Идем по документу сверху вниз и выписываем **каждое** изменение. Для каждого:

- порядковый номер и рабочее название — терминами продукта, как в источнике;
- **цитата-опора** из `01_source_text.md` (1–2 предложения дословно) — на нее потом
  опирается QA;
- страница PDF;
- есть ли иллюстрация: файл из `assets/images/raw/` или пометка «картинка не загрузилась»;
- какие в источнике есть детали: цифры, тарифы, ограничения, названия разделов.

Ничего не пропускаем: блок «Другие обновления месяца» разбираем по пунктам, каждый — своя строка.

### Шаг 4. Разделить на major и minor

По пяти критериям из style guide: самостоятельность функции, влияние на сценарий, объем
фактуры, наличие картинки, широта аудитории. Совпало 3–5 — `major`, 1–2 — `minor`.

Для каждого `major` пишем одной строкой, почему он крупный. Спорные случаи выносим
отдельным списком «на решение редактора» — не решаем молча.

### Шаг 5. Свести инвентарь картинок

Из `assets/images/extract_report.json`:

- какие картинки — иллюстрации, какие служебные (логотипы, иконки, промо);
- к какому обновлению относится каждая иллюстрация — по контексту над картинкой и по
  тому, что на ней видно (картинку нужно открыть и посмотреть, а не гадать по имени файла);
- где скрипт нашел **заглушку непрогрузившейся картинки** — значит, у этого обновления
  скриншота нет, и его придется запрашивать у продуктовой команды;
- нужен ли ручной кроп: картинка склеена с большим объемом текста или содержит несколько
  несвязанных экранов.

### Шаг 6. Заполнить шаблон

Заполнить `templates/monthly_updates_source_facts.md`, сохранить как
`02_source_facts.md`. Показать редактору сводку: сколько обновлений найдено, сколько
крупных, сколько картинок, где пробелы.

## Gate

Не передавать дальше, если:

- в реестре меньше обновлений, чем в PDF, — пересчитать по документу;
- у обновления нет цитаты-опоры из источника;
- в реестр попал текст рассылки, промо вебинара или строка-эхо;
- иллюстрации не разнесены по обновлениям.

## Выход

`01_source_text.md`, `02_source_facts.md`, разложенные `assets/images/`.
Следующий навык — `monthly-updates-writer`.
