# Workflow: monthly product updates

> Второй тип статьи в репозитории — **`monthly_product_updates`**, ежемесячный обзор
> обновлений Кайтена. Не SEO-статья: интента и ключей нет, источник фактуры один —
> внутренний PDF с релизами за месяц. Конвейер SEO-статей
> ([`seo_article_pipeline.md`](seo_article_pipeline.md)) этим не затрагивается и работает как раньше.

## Принцип

Тот же, что и в основном конвейере: AI делает черновую часть, редактор отвечает за
качество. Разница в источнике и в гейтах.

**Источник истины — приложенный PDF.** Внешний ресерч по фактуре статьи не нужен и по
умолчанию запрещен. Нельзя придумывать функции, ограничения, тарифы, сценарии, цифры,
даты, ссылки и технические возможности. Не хватает информации — пометка
`[НУЖНО УТОЧНИТЬ: вопрос]`, а не догадка.

Редакционные правила формата — [`knowledge/monthly_updates_style_guide.md`](../knowledge/monthly_updates_style_guide.md).
Тон и запреты — `knowledge/editorial_policy.md`, `knowledge/forbidden_phrases.md`.

## Канонические имена файлов

Папка статьи: `articles/YYYY-MM-obnovleniya-<месяц>/` (копия
`articles/_MONTHLY_UPDATES_FOLDER_TEMPLATE/`).

```
00_intake.md            — вводные редактора: PDF, месяц, год, комментарии
01_source_text.md       — машинная выгрузка текста PDF (создает tools/pdf_extract.py)
02_source_facts.md      — реестр обновлений: полный список, major/minor, инвентарь картинок
03_outline.md           — H1-варианты, deck, лид, структура H2/H3, куда какая картинка  🛑 STOP 1
04_draft.md             — черновик статьи с картинками и подписями                      🛑 STOP 2
05_editorial_review.md  — прогон по редполитике
06_image_manifest.md    — манифест изображений для редактора и дизайнера
07_qa_report.md         — сверка статьи с исходным PDF                                  🛑 STOP 3
08_publication_pack.md  — упаковка к публикации
assets/images/          — итоговые картинки со смысловыми именами
assets/images/raw/      — сырые картинки из PDF (машинные имена, в статью не идут)
assets/images/pages/    — рендеры страниц PDF для сверки (по флагу --render-pages)
pipeline_status.md      — живой статус
```

## Stop-points

- **🛑 STOP 1 — после `03_outline.md`:** редактор утверждает H1, deck и деление на
  крупные/мелкие обновления. Без этого черновик не пишем.
- **🛑 STOP 2 — после `04_draft.md`:** редактор смотрит черновик: не съехал ли он в
  release notes, не раздуты ли разделы, не появилось ли отсебятины.
- **🛑 STOP 3 — после `07_qa_report.md`:** `unsupported claims > 0` или потерянные
  обновления → возврат на правку. К упаковке идем только с чистым отчетом.

## Этапы

### 00_intake.md — Intake

1. **Навык:** — (заполняет редактор).
2. **Читает:** ничего.
3. **Создает:** `00_intake.md` — путь к PDF, месяц и год публикации, комментарии
   редактора, известные приоритеты («главное обновление месяца — дашборды»).
4. **Готово:** PDF на месте, месяц и год заданы явно или надежно определяются из документа.
5. **Стоп:** нет PDF или непонятен месяц → спросить редактора, не угадывать.
6. **Дальше:** → `monthly-updates-source`.

### 01_source_text.md — Разбор PDF

1. **Навык:** `monthly-updates-source` (запускает `tools/pdf_extract.py`).
2. **Читает:** исходный PDF.
3. **Создает:** `01_source_text.md`, `assets/images/raw/*`, `assets/images/extract_report.md|json`.
4. **Готово:** текст выгружен постранично, картинки разложены, служебные помечены,
   заглушки непрогрузившихся картинок и строки-эхо перечислены отдельно.
5. **Стоп:** скрипт не отработал (нет PyMuPDF, битый PDF) → чинить, руками текст не набивать.
6. **Дальше:** → `02_source_facts.md`.
7. **Нельзя:** править `01_source_text.md` руками — это машинная выгрузка и источник истины.

### 02_source_facts.md — Реестр обновлений

1. **Навык:** `monthly-updates-source`.
2. **Читает:** `01_source_text.md`, отчет извлечения, `00_intake.md`,
   `knowledge/monthly_updates_style_guide.md`.
3. **Создает:** `02_source_facts.md` по `templates/monthly_updates_source_facts.md`.
4. **Готово:** пронумерован **полный** список обновлений из PDF, у каждого — цитата-опора
   из источника, деление на `major` / `minor`, обоснование по пяти критериям важности,
   инвентарь картинок (какая к какому обновлению), список спорных случаев и пробелов.
5. **Стоп:** какое-то изменение из PDF не попало в реестр → достроить реестр.
6. **Дальше:** → `monthly-updates-writer`.
7. **Нельзя:** отбрасывать пункты «на глаз»; тащить в реестр строки-эхо и служебный текст
   рассылки (тема письма, прехедер, приветствие, промо вебинара).

### 03_outline.md — Структура · 🛑 STOP 1

1. **Навык:** `monthly-updates-writer`.
2. **Читает:** `02_source_facts.md`, `knowledge/monthly_updates_style_guide.md`.
3. **Создает:** `03_outline.md` по `templates/monthly_updates_outline.md`.
4. **Готово:** 2–3 варианта H1 с рекомендуемым, deck, тезис лида, порядок H2/H3, для
   каждого раздела — на какие пункты реестра он опирается и какая картинка встает.
5. **🛑 STOP 1:** редактор утверждает заголовок, deck и деление на крупные/мелкие.
6. **Дальше:** структура утверждена → черновик.
7. **Нельзя:** порядок «как в PDF» вместо порядка по значимости; H2 под каждую мелочь.

### 04_draft.md — Черновик · 🛑 STOP 2

1. **Навык:** `monthly-updates-writer` + `kaiten-editorial` (тон).
2. **Читает:** `03_outline.md`, `02_source_facts.md`, style guide, `editorial_policy`,
   `forbidden_phrases`.
3. **Создает:** `04_draft.md` — H1, deck, лид, разделы, картинки с подписями, финал.
4. **Готово:** каждое обновление из реестра либо в тексте, либо осознанно отложено;
   картинки вставлены markdown-плейсхолдерами со смысловыми именами; спорные места
   помечены `[НУЖНО УТОЧНИТЬ: …]`.
5. **🛑 STOP 2:** редактор смотрит черновик.
6. **Дальше:** → манифест изображений.
7. **Нельзя:** пересказ PDF абзац за абзацем; «Теперь» в начале каждого абзаца; выгода,
   не следующая из фактуры.

### 05_editorial_review.md — Редакционная вычитка

1. **Навык:** `ai-pre-review` (рубрика и Vale) + `kaiten-editorial`.
2. **Читает:** `04_draft.md`, `knowledge/` (`editorial_policy`, `forbidden_phrases`,
   `bad_patterns`, `monthly_updates_style_guide`), `styles/Kaiten/`.
3. **Создает:** `05_editorial_review.md` — замечания HARD/SOFT, без переписывания.
4. **Готово:** разобраны тон, штампы, «ё», позиционирование, длина предложений, повторы,
   подписи к картинкам, соответствие формату обзора.
5. **Дальше:** правки внесены в `04_draft.md` → манифест.
6. **Нельзя:** пропускать HARD-нарушения; проверять «на глаз» без style guide.

### 06_image_manifest.md — Манифест изображений

1. **Навык:** `monthly-updates-writer`.
2. **Читает:** `04_draft.md`, `assets/images/extract_report.json`, style guide.
3. **Создает:** `06_image_manifest.md` по `templates/monthly_updates_image_manifest.md`
   и раскладывает финальные файлы в `assets/images/` со смысловыми именами.
4. **Готово:** по каждой картинке — файл, страница PDF, раздел статьи, подпись, alt,
   `manual_crop_required`, статус. Отдельным списком — разделы, где скриншота нет и его
   нужно запросить.
5. **Дальше:** → QA.
6. **Нельзя:** имена вида `image1.png`, `page4_crop2.png`; плохой кроп вместо честного
   `manual_crop_required: true`; выдуманный интерфейс вместо реального скриншота.

### 07_qa_report.md — Сверка с источником · 🛑 STOP 3

1. **Навык:** `monthly-updates-qa`.
2. **Читает:** `04_draft.md`, `02_source_facts.md`, `01_source_text.md`, `06_image_manifest.md`.
3. **Создает:** `07_qa_report.md` по `templates/monthly_updates_qa_report.md`.
4. **Готово:** сводка `Source updates found / Included in article / Major sections /
   Minor updates / Images extracted / Manual image review required / Unsupported claims`,
   плюс разбор по пунктам: цифры, тарифы, ограничения, названия функций, соответствие
   картинок разделам, смысловые повторы, соответствие deck главным обновлениям.
5. **🛑 STOP 3:** `Unsupported claims > 0` или потерянные обновления → возврат в `04_draft.md`.
6. **Дальше:** отчет чистый → упаковка.
7. **Нельзя:** «проверил, все хорошо» без построчной сверки с реестром.

### 08_publication_pack.md — Публикационный пакет

1. **Навык:** `package-for-cms` (в режиме обзора обновлений).
2. **Читает:** `04_draft.md`, `07_qa_report.md`, `06_image_manifest.md`,
   `knowledge/internal-links-map.md`.
3. **Создает:** `08_publication_pack.md` — финальный H1, deck, slug, Title ≤70,
   Description ≤160, теги, перелинковка, список изображений с alt, чек-лист публикации.
4. **Готово:** пакет собран, чек-лист закрыт, открытые вопросы к редактору перечислены.
5. **Нельзя:** публиковать с незакрытыми `[НУЖНО УТОЧНИТЬ]` и с разделами без нужных
   скриншотов.

## Как запустить

```bash
python tools/pdf_extract.py --pdf "Обновления август _ Kaiten.pdf" --out "articles/2026-08-obnovleniya-avgusta" --render-pages
```

Дальше — по этапам выше. Формулировка запуска для агента:

```text
Собери обзор обновлений: article_type = monthly_product_updates,
source = "Обновления август _ Kaiten.pdf", month = август, year = 2026
```

Агент читает `skills/monthly-updates-source/SKILL.md`, затем
`skills/monthly-updates-writer/SKILL.md`, затем `skills/monthly-updates-qa/SKILL.md`
и останавливается на каждом stop-point.

## Кто проверяет на stop-points

- STOP 1 — редактор (заголовок, deck, деление обновлений).
- STOP 2 — редактор (черновик).
- STOP 3 — по QA-отчету + редактор.

## Чем этот конвейер отличается от SEO-статей

| | SEO-статья | Обзор обновлений |
| --- | --- | --- |
| Источник | ресерч, выдача, конкуренты | один PDF с фактурой |
| Бриф и ревью брифа | обязательны (STOP 1) | не нужны, вместо них реестр обновлений |
| Внешний ресерч | обязателен | по умолчанию запрещен |
| SEO-пакет | ключи, интент, Баден-Баден | slug, title, description без ключевой нагрузки |
| Скоринг 0–100 | обязателен | заменен QA-сверкой с источником |
| Визуальный этап | `visual-producer-kaiten`, генерация схем | картинки берутся из PDF, не рисуются |
