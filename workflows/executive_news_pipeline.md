# Workflow: новость компании для Executive.ru

> Редакционный цикл для **новостей Кайтена на внешней площадке Executive.ru** (раздел
> «Новости компаний»). **Путь тот же, что у статьи блога** ([`seo_article_pipeline.md`](seo_article_pipeline.md)):
> те же этапы, те же имена файлов, те же стоп-точки и порог оценки 90+. Отличия — в
> содержании этапов: вместо SEO-вводных проверяем повод по правилам площадки, вместо
> перелинковки и картинок — формат новости.
>
> Общие правила — [CLAUDE.md](../CLAUDE.md). Правила площадки —
> [`external_platforms/e-xecutive/platform_rules.md`](../external_platforms/e-xecutive/platform_rules.md),
> примеры — [`examples.md`](../external_platforms/e-xecutive/examples.md). Навык —
> [`executive-news`](../skills/executive-news/SKILL.md). Статус новости ведется в ее
> `pipeline_status.md` (шаблон — `templates/executive_news_pipeline_status.md`).

## Принцип

AI делает черновую часть, редактор отвечает за повод на входе и качество на выходе.
**Редактор — финальный владелец качества.** Между этапами есть stop-points: без решения
редактора двигаться дальше нельзя. Новость отправляет на площадку человек, не агент.

## Канонические имена файлов

Папка новости — `external_platforms/e-xecutive/news/YYYY-MM-тема/`, копия `_NEWS_FOLDER_TEMPLATE/`.

`00_intake` → `01_brief` → `01_brief_review` → `02_source_text` + `02_research` →
`03_outline` → `04_draft` → `05_editorial_review` → `06_article_score` → `07_revision_task` →
`08_revised_draft` → `09_rescore` → `10_publication_pack`.

Этапов `11`–`13` (визуалы) нет: новости компаний на площадке выходят без картинок.

## Stop-points (сводка)

- **STOP 1 — после `01_brief_review`:** нельзя писать новость, пока бриф не `APPROVED`. Здесь
  же решается судьба повода: если событие старше трех дней, решение принимает редактор.
- **STOP 2 — после `03_outline`:** нельзя писать черновик, пока заголовок, анонс и план
  абзацев не одобрены.
- **STOP 3 — после `04_draft`:** редактор смотрит, не вышла ли новость рекламной, скомканной
  или пересказом источника.
- **STOP 4 — после `06_article_score`:** оценка < 90 → правки (`07`–`09`); 90+ → пакет.

## Этапы

### 00_intake.md — Intake
1. **Skill:** — (заполняет редактор по `templates/executive_news_intake_template.md`).
2. **Читает:** повод — релиз, внутренний документ продукта, публикацию в СМИ, выгрузку аналитики.
3. **Создает:** `00_intake.md`.
4. **Готово:** известны повод, тип новости, источник, дата события, плановая дата отправки,
   спикер, кто подтверждает факты и кто отправляет.
5. **Стоп:** нет источника или даты события — не идти дальше, задать вопросы редактору.
6. **Дальше:** → `executive-news`, бриф.
7. **Нельзя пропускать:** дату события — от нее зависит, пропустит ли новость модерация.

### 01_brief.md — Brief
1. **Skill:** `executive-news` (этап 01).
2. **Читает:** `00_intake.md`, источник, `platform_rules.md`, [ленту компании на площадке](https://www.e-xecutive.ru/companies/1998937-kaiten-softver/news),
   журнал публикаций и примеры (`external_platforms/e-xecutive/`), `knowledge/products.md`,
   `editorial_policy`, `forbidden_phrases`.
3. **Создает:** `01_brief.md` по `templates/executive_news_brief.md`.
4. **Готово:** проверен повод по пяти правилам площадки; сформулирован угол — главный факт;
   2–3 варианта заголовка; структура по типу новости; список обязательной фактуры и цитат;
   продуктовая связка; ссылка, теги; что не выносим из источника; анти-паттерны.
5. **Стоп:** нет критичных вводных → блок «Вопросы перед новостью», не выдумывать.
6. **Дальше:** → ревью брифа.
7. **Нельзя пропускать:** проверку повода; угол-тему вместо угла-факта («исследование о
   перерывах» вместо «вина за перерывы зависит от должности»).

### 01_brief_review.md — Brief review · 🛑 STOP 1
1. **Skill:** `executive-news` (этап 01, ревью).
2. **Читает:** `01_brief.md`, `00_intake.md`, `platform_rules.md`, примеры.
3. **Создает:** `01_brief_review.md` по `templates/executive_news_brief_review.md` — статус
   **APPROVED / NEEDS_REVISION / BLOCKED** и оценка 0–100.
4. **Готово:** статус проставлен, критичные проблемы описаны, есть список «что нужно для
   APPROVED».
5. **🛑 STOP 1:** **нельзя писать новость, пока бриф не `APPROVED`.** Риск по сроку
   принимает только редактор, письменно.
6. **Дальше:** только при `APPROVED` → research.
7. **Нельзя пропускать:** APPROVED при функции, которая еще не у клиентов; при поводе,
   который уже был на площадке; при исследовании без методики.

### 02_source_text.md + 02_research.md — Research
1. **Skill:** `executive-news` (этап 02) + `product-fact-check` для фактов о продукте.
2. **Читает:** источник, другие публикации о том же событии (веб-поиск по ключевым цифрам),
   `knowledge/products.md` со сверкой по [faq-ru.kaiten.site](https://faq-ru.kaiten.site/).
3. **Создает:** `02_source_text.md` — дословная выгрузка всех источников с датами;
   `02_research.md` по `templates/executive_news_research.md` — реестр фактов с опорой,
   цитаты, расхождения, методика или доступность, продуктовые факты, открытые вопросы.
4. **Готово:** каждый факт будущей новости есть в реестре с дословной опорой; внутреннее
   отмечено; вывод «можно ли к структуре».
5. **Стоп:** источник недоступен целиком — не восстанавливать по памяти.
6. **Дальше:** → outline.
7. **Нельзя пропускать:** выдуманные цифры; цифры из подвыборок неизвестного размера в
   заголовке; продуктовые факты без сверки.

### 03_outline.md — Outline · 🛑 STOP 2
1. **Skill:** `executive-news` (этап 03).
2. **Читает:** `01_brief.md`, `02_research.md`, ближайший пример из `examples/`.
3. **Создает:** `03_outline.md` по `templates/executive_news_outline.md` — варианты
   заголовка, анонс, план абзацев с фактами из реестра, место цитат, ссылка, теги.
4. **Готово:** структура по типу новости, первый абзац содержит всю новость, финал —
   доступность, методика или условия; объем в оптимуме 2–3 тыс. знаков.
5. **🛑 STOP 2:** **нельзя писать черновик, пока структура не одобрена редактором.**
6. **Дальше:** → черновик.
7. **Нельзя пропускать:** лид-разгон вместо новости; абзацы «для объема».

### 04_draft.md — Draft · 🛑 STOP 3
1. **Skill:** `executive-news` (этап 04) + `kaiten-editorial` (тон, инфостиль).
2. **Читает:** `03_outline.md`, `02_research.md`, `platform_rules.md`,
   `knowledge/forbidden_phrases.md`.
3. **Создает:** `04_draft.md` по `templates/executive_news_draft.md`.
4. **Готово:** `perl tools/news_check.pl` без ошибок, кроме открытых вопросов;
   `vale_lite.pl` без HARD; self-check заполнен.
5. **🛑 STOP 3:** **редактор смотрит черновик** — не реклама ли, выдержано ли третье лицо,
   не пересказ ли источника.
6. **Дальше:** → editorial review.
7. **Нельзя пропускать:** «мы» и «вы»; рекламные оценки; цитаты, которых нет в источнике.

### 05_editorial_review.md — Editorial review
1. **Skill:** `ai-pre-review` по рубрике `templates/executive_news_score.md`.
2. **Читает:** `04_draft.md`, `02_research.md`, `02_source_text.md`, `platform_rules.md`,
   `styles/Kaiten/`, примеры.
3. **Создает:** `05_editorial_review.md` — механика (`news_check`, `vale_lite`), сверка
   каждого утверждения с реестром (`Unsupported claims: N`), замечания HARD/SOFT без
   переписывания.
4. **Готово:** разобраны первый абзац, заголовок и анонс, фактура, полнота по типу, тон,
   продуктовая точность, язык, связность.
5. **Стоп:** — (ревью — вход в оценку).
6. **Дальше:** → `06_article_score`.
7. **Нельзя пропускать:** молчаливую правку вместо замечаний; «примерно совпадает» вместо
   дословной сверки цифр.

### 06_article_score.md — Article score · 🛑 STOP 4
1. **Skill:** `ai-pre-review` (рубрика `templates/executive_news_score.md`, 100 баллов).
2. **Читает:** `04_draft.md`, `05_editorial_review.md`, `01_brief.md`, `02_research.md`.
3. **Создает:** `06_article_score.md` — оценка по 10 критериям, итог 0–100, решение.
4. **Готово:** балл и решение; при < 90 — список правок с приоритетами.
5. **🛑 STOP 4:** **< 90, любой HARD ниже порога или `Unsupported claims` > 0 → правки**
   (`07_revision_task` → `08_revised_draft`). **90+ → публикационный пакет.**
6. **Дальше:** по правилу выше.
7. **Нельзя пропускать:** 90+ при незакрытом `[НУЖНО УТОЧНИТЬ]` в тексте.

### 07_revision_task.md — Revision task
1. **Skill:** редактор; `executive-news` собирает ТЗ из `05` и `06`.
2. **Читает:** `05_editorial_review.md`, `06_article_score.md`, `04_draft.md`.
3. **Создает:** `07_revision_task.md` — что, почему, где, **что не трогать**.
4. **Готово:** точечное ТЗ с приоритетами 🔴/🟡.
5. **Стоп:** —.
6. **Дальше:** → `08_revised_draft`.
7. **Нельзя пропускать:** правки, которые меняют угол; новые факты без реестра.

### 08_revised_draft.md — Revised draft
1. **Skill:** `executive-news` (этап 08) + `kaiten-editorial`.
2. **Читает:** `07_revision_task.md`, `04_draft.md`, `02_research.md`.
3. **Создает:** `08_revised_draft.md` в формате черновика — точечные правки, не переписывание.
4. **Готово:** правки внесены, `news_check.pl` без ошибок.
5. **Стоп:** —.
6. **Дальше:** → `09_rescore`.
7. **Нельзя пропускать:** смену угла; воду для объема.

### 09_rescore.md — Rescore
1. **Skill:** `ai-pre-review` (повторная оценка по той же рубрике).
2. **Читает:** `08_revised_draft.md`, `07_revision_task.md`, `06_article_score.md`.
3. **Создает:** `09_rescore.md` — закрыты ли правки, новый балл, решение.
4. **Готово:** балл обновлен.
5. **🛑 (возврат к STOP 4):** < 90 — снова правки; 90+ → пакет.
6. **Дальше:** 90+ → `10_publication_pack`.
7. **Нельзя пропускать:** незакрытые 🔴-замечания.

### 10_publication_pack.md — Publication pack
1. **Skill:** `executive-news` (этап 10).
2. **Читает:** финальный черновик (`08_revised_draft` или `04_draft`), оценку 90+, журнал
   публикаций площадки.
3. **Создает:** `10_publication_pack.md` по `templates/executive_news_publication_pack.md` —
   поля для формы площадки без markdown, финальная проверка, дата отправки и крайний срок
   по правилу трех дней, журнал модерации.
4. **Готово:** пакет можно вставить в форму площадки как есть.
5. **Стоп:** создается **только** после оценки 90+. Отправляет человек.
6. **Дальше:** публикация → ссылка в пакет → строка в журнал публикаций → текст в
   `examples/` и строка в `examples.md`.
7. **Нельзя пропускать:** запись в журнал и в примеры — без нее следующая новость может
   попасть в тот же день, а примеры перестанут расти.

---

## Кто проверяет на stop-points

- STOP 1 — редактор (по ревью брифа).
- STOP 2 — редактор.
- STOP 3 — редактор (беглый взгляд на черновик).
- STOP 4 — по оценке (`ai-pre-review`) + редактор.

## Сквозные навыки

`kaiten-editorial` (тон, инфостиль, название продукта), `ai-pre-review` (редактура и оценка
по рубрике новостей), `product-fact-check` (факты о продукте по faq-ru.kaiten.site).

`visual-producer-kaiten`, `make-cover`, генерация изображений в этом конвейере не участвуют.

## Чем путь новости отличается от пути статьи

| Этап | Статья блога | Новость для Executive.ru |
| --- | --- | --- |
| 01 Brief | SEO-интент, ключи, боль читателя | проверка повода по правилам площадки, угол-факт |
| 02 Research | источники, конкуренты, перелинковка | дословный источник и реестр фактов с опорой |
| 03 Outline | H2/H3 | заголовок, анонс, план абзацев |
| 05–06 Оценка | рубрика `ai_review.md`, 11 критериев | рубрика `executive_news_score.md`, 10 критериев + `news_check.pl` |
| 10 Пакет | Title, Description, slug, перелинковка | поля формы площадки, дата отправки, журнал модерации |
| 11–13 Визуалы | есть | нет |
