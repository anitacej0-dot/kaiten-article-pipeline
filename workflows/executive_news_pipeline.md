# Workflow: новость компании для Executive.ru

> Редакционный цикл для **новостей Кайтена на внешней площадке Executive.ru** (раздел
> «Новости компаний»). Общие правила — [CLAUDE.md](../CLAUDE.md). Правила площадки и наш
> формат — [`external_platforms/e-xecutive/platform_rules.md`](../external_platforms/e-xecutive/platform_rules.md),
> эталоны — [`examples.md`](../external_platforms/e-xecutive/examples.md). Навык —
> [`executive-news`](../skills/executive-news/SKILL.md). Статус конкретной новости ведется в
> ее `pipeline_status.md`.

## Принцип

Это **не SEO-статья и не материал блога**: ключей, брифа, перелинковки и картинок нет.
Новость пишется по правилам чужой площадки, и модерация отклоняет все, что их нарушает.
Поэтому работа начинается не с текста, а с проверки повода.

Три вещи, за которые отвечает конвейер:

1. **Повод проходит модерацию:** событие не старше трех дней, о нем еще не писали, оно уже
   случилось и доступно клиентам.
2. **Ничего не выдумано:** каждая цифра, факт и цитата — из источника, дословно.
3. **Формат площадки соблюден:** заголовок до 70 знаков с глаголом, анонс до 160, текст 2–3
   тыс. знаков от третьего лица, не больше одной внешней ссылки.

Скоринга по рубрике на 100 баллов здесь нет: новость короткая, качество держат правила
площадки, реестр фактуры и чек-лист `kaiten-editorial`.

## Канонические имена файлов

Папка новости — `external_platforms/e-xecutive/news/ГГГГ-ММ-тема/`, копия
`_NEWS_FOLDER_TEMPLATE/`.

`00_intake` → `01_source_text` + `01_fact_sheet` → `02_draft` → `03_qa_report` →
`04_publication_pack`.

## Stop-points (сводка)

- **🛑 Проверка повода — после `00_intake`:** событие старше трех дней на дату отправки,
  повтор, функция не у клиентов или анонс мероприятия → стоп, вопрос редактору.
- **🛑 STOP 1 — после `02_draft`:** редактор смотрит заголовок, анонс, текст и открытые
  вопросы.
- **🛑 STOP 2 — после `03_qa_report`:** `Unsupported claims: 0`, открытых вопросов 0,
  `news_check.pl` без ошибок. Иначе — возврат в черновик.
- **🛑 STOP 3 — `04_publication_pack`:** новость отправляет человек с доступом к кабинету
  компании. Агент не отправляет.

## Этапы

### 00_intake.md — Intake и проверка повода

1. **Skill:** редактор заполняет вводные, `executive-news` (этап 0) проверяет повод.
2. **Читает:** источник, [ленту компании на площадке](https://www.e-xecutive.ru/companies/1998937-kaiten-softver/news),
   журнал публикаций в `external_platforms/e-xecutive/README.md`, `platform_rules.md`.
3. **Создает:** `00_intake.md` с блоком «Проверка повода».
4. **Готово:** известны повод, тип новости, источник, дата события, плановая дата отправки,
   спикер и кто подтверждает факты.
5. **🛑 Стоп:** любой ответ «нет» или «не знаю» в проверке повода — вопрос редактору до
   черновика.
6. **Дальше:** повод прошел → источник и реестр.
7. **Нельзя пропускать:** проверку свежести события. Новость, написанная по устаревшему
   поводу, — потерянная работа.

### 01_source_text.md + 01_fact_sheet.md — Источник и реестр фактуры

1. **Skill:** `executive-news` (этап 1).
2. **Читает:** источник из intake, другие публикации о том же событии (веб-поиск),
   `knowledge/products.md`, `platform_rules.md` — раздел «Что не выносим».
3. **Создает:** `01_source_text.md` — дословная выгрузка всех источников с датами;
   `01_fact_sheet.md` — реестр: факт, опора, публикуем или нет, расхождения, методика,
   открытые вопросы.
4. **Готово:** каждый факт будущей новости есть в реестре с дословной опорой; внутреннее
   отмечено; расхождения между источниками разобраны.
5. **Стоп:** источник недоступен целиком — не восстанавливать по памяти.
6. **Дальше:** → черновик.
7. **Нельзя пропускать:** проверку методики у исследований; цифры из подвыборок
   неизвестного размера в заголовке.

### 02_draft.md — Черновик · 🛑 STOP 1

1. **Skill:** `executive-news` (этап 2) + `kaiten-editorial` (тон и инфостиль).
2. **Читает:** `01_fact_sheet.md`, `platform_rules.md` (структура по типу), `examples.md`,
   `knowledge/forbidden_phrases.md`.
3. **Создает:** `02_draft.md` по шаблону — заголовок, анонс, текст, ссылка, теги,
   «Служебное» с вариантами заголовка и открытыми вопросами.
4. **Готово:** `perl tools/news_check.pl <02_draft.md>` без ошибок, кроме открытых
   вопросов; `vale_lite.pl` без ошибок.
5. **🛑 STOP 1:** редактор утверждает заголовок, анонс и текст.
6. **Дальше:** → QA.
7. **Нельзя пропускать:** первое лицо и «вы»; рекламные оценки; цитаты, которых нет в
   источнике.

### 03_qa_report.md — QA · 🛑 STOP 2

1. **Skill:** `executive-news` (этап 3).
2. **Читает:** `02_draft.md`, `01_fact_sheet.md`, `01_source_text.md`, `platform_rules.md`.
3. **Создает:** `03_qa_report.md` — механика, сверка каждого утверждения с реестром,
   цитаты, чек-лист площадки из десяти пунктов, чек-лист редполитики, решение.
4. **Готово:** `Unsupported claims: 0`, открытых вопросов 0, все цитаты дословны.
5. **🛑 STOP 2:** не выполнено хоть одно условие → возврат в черновик или вопрос редактору.
6. **Дальше:** → пакет.
7. **Нельзя пропускать:** «примерно совпадает» вместо дословной сверки цифр.

### 04_publication_pack.md — Пакет для отправки · 🛑 STOP 3

1. **Skill:** `executive-news` (этап 4).
2. **Читает:** финальный `02_draft.md`, `03_qa_report.md`.
3. **Создает:** `04_publication_pack.md` — поля для площадки без markdown, плановая дата и
   крайний срок по правилу трех дней, кто отправляет, журнал модерации.
4. **Готово:** пакет можно вставить в форму площадки как есть.
5. **🛑 STOP 3:** отправляет человек. После публикации — ссылка в пакет, строка в журнал
   публикаций площадки, статус в `pipeline_status.md`.
6. **Дальше:** —
7. **Нельзя пропускать:** запись в журнал публикаций — без нее следующая новость может
   попасть в тот же день или повторить событие.

## Кто проверяет на stop-points

- Проверка повода — `executive-news` + редактор.
- STOP 1 — редактор.
- STOP 2 — `executive-news` + редактор.
- STOP 3 — редактор или ответственный за кабинет компании на площадке.

## Сквозные навыки

`kaiten-editorial` (тон, инфостиль, название продукта), `product-fact-check` — если в
продуктовой новости нужно сверить факты по faq-ru.kaiten.site.

`visual-producer-kaiten`, `make-cover`, генерация изображений в этом конвейере не участвуют:
новости компаний на площадке выходят без иллюстраций.
