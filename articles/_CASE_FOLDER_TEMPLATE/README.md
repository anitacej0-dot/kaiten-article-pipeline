# Шаблон папки: кейс-рерайт

Заготовка для кейса типа `case_rewrite` — материал уже вышел на сторонней площадке, мы
дублируем его в блог. Полный цикл —
[`workflows/case_rewrite_pipeline.md`](../../workflows/case_rewrite_pipeline.md).
Формат кейса — [`knowledge/case_style_guide.md`](../../knowledge/case_style_guide.md),
теги и карточка — [`knowledge/case_tagging.md`](../../knowledge/case_tagging.md).

Это **не SEO-статья**: брифа, интента и подбора ключей здесь нет. Скоринг качества и
проверка уникальности — есть.

## Как создать новый кейс

1. **Скопируй эту папку** в `articles/YYYY-MM-case-<компания>/`
   (например, `articles/2026-09-case-kolibri/`).
2. **Заполни `00_intake.md`:** ссылка на исходную публикацию, компания, спикер, контакт
   для согласования, тип кейса, ограничения клиента, скриншоты.
3. **Выгрузи исходник дословно** — по нему проверяются факты и считается уникальность:
   ```bash
   curl -sL --max-time 45 -A "Mozilla/5.0" "<ссылка>" -o source.html
   ```
   Текст сохрани как `01_source_text.md`. Если исходник пришел PDF:
   ```bash
   pdftotext -raw -enc UTF-8 "<файл.pdf>" 01_source_text.md
   ```
4. **Запусти `case-source`** → `01_source_map.md` (реестр фактуры с цитатами-опорами).
5. **Запусти `case-rewriter`** → `02_outline.md`.
   **🛑 STOP 1:** редактор утверждает H1, описание под заголовком и деление на разделы.
6. **Черновик** → `03_draft.md`. **🛑 STOP 2:** редактор смотрит текст.
7. **Редактура и скоринг** (`ai-pre-review`) → `04_editorial_review.md`, `05_case_score.md`.
   **🛑 STOP 3:** меньше 90 → правки в черновик и пересчет.
8. **Запусти `case-qa`** → `06_qa_report.md`.
   **🛑 STOP 4:** уникальность ниже 85%, заспамленность 58%+ или неподтвержденный факт →
   возврат.
9. **Согласование с героем кейса** → `07_client_approval.md`.
   **🛑 STOP 5:** без письменного согласия не публикуем.
10. **Упаковка** (`case-package`) → `08_publication_pack.md`.

## Что в папке

- `00_intake.md` — вводные редактора (заполнить).
- `pipeline_status.md` — живой статус по этапам (обновлять).
- `assets/images/` — картинки кейса.

Остальное создается по ходу: `01_source_text.md`, `01_source_map.md`, `02_outline.md`,
`03_draft.md`, `04_editorial_review.md`, `05_case_score.md`, `06_qa_report.md`,
`07_client_approval.md`, `08_publication_pack.md`.

## Самопроверка уникальности

До прогона в text.ru:

```bash
perl tools/shingle_check.pl articles/<папка>/03_draft.md articles/<папка>/01_source_text.md
```

Скрипт показывает долю совпавших цепочек слов и самые длинные узнаваемые куски.
Ориентир: эталонный рерайт кейса КЛБР дает около 4%, и все длинные совпадения там —
названия наград, имена проектов и цифры. Гейт ставит только text.ru: уникальность 85%+,
заспамленность ниже 58%.

## Чего здесь нельзя

- Придумывать цифры, функции, сроки и результаты — источник истины только исходник.
  Не хватает данных — `[НУЖНО УТОЧНИТЬ: вопрос]`.
- Пересказывать исходник абзац за абзацем: материал пересобирается редакционно, иначе
  уникальности не будет.
- Оставлять текст от первого лица.
- Дорисовывать интерфейс продукта. Нет скриншота — раздел выходит без картинки, а в пакете
  остается запрос скриншота у клиента.
- Публиковать без письменного согласия героя кейса.

> Папка `_CASE_FOLDER_TEMPLATE` — только образец. Не веди в ней реальный кейс, копируй под
> новый материал.
