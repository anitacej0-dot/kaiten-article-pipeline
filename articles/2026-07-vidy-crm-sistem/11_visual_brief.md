# Visual brief: Виды и типы CRM-систем

> Создает `visual-producer-kaiten` после publication pack. Все визуалы обязаны соответствовать
> `.claude/skills/design-system-kaiten-v01/SKILL.md`. Статью не переписываем — только визуальная часть.

## 1. Название статьи
Какие бывают виды CRM-систем: классификация, примеры и как выбрать свой тип

## 2. Ссылка на статью / папку материала
`articles/2026-07-vidy-crm-sistem/` — финальный текст: `08_revised_draft.md`; пакет: `10_publication_pack.md`.

## 3. Главный угол статьи
Три «типа» CRM — это не три конкурирующих продукта, а три задачи: операционная (руки —
вести сделки), аналитическая (голова — понимать), коллаборационная (связки — соединять
отделы вокруг клиента). Почти все реальные системы комбинированные. Визуалы должны
поддержать именно эту рамку.

## 4. Визуальная задача
Помочь читателю (а) быстро уложить в голове три типа через задачу, (б) увидеть, почему
клиент теряется на стыках отделов, (в) по симптому выйти на нужный тип. Не украшать —
объяснять. Меньше визуалов, но по делу.

## 5. Что нужно объяснить визуально
- три типа CRM = три задачи (руки/голова/связки) — ключевая схема;
- как клиент проходит через отделы и где теряется контекст (коллаборационная CRM);
- диагностика «симптом → тип CRM» (практическое ядро);
- (вспом.) три независимые оси классификации — задача / облако-коробка / универсальная-отраслевая;
- обложка — «навести порядок в клиентах» / три задачи CRM.

## 6. Что не нужно визуализировать
- определение CRM, историческую врезку, список примеров систем — это текст, картинка не нужна;
- сравнительную таблицу типов — она уже есть в тексте, дублировать картинкой не надо;
- интерфейс конкретных CRM-систем (Bitrix24, amoCRM и т.п.) — чужой интерфейс не показываем;
- «красивые» абстракции без смысла, стоки, случайные иллюстрации.

## 7. Обложка
Идея: из хаоса — к порядку. Разрозненные каналы/заявки (точки, стрелки в разные стороны)
собираются в аккуратную структуру. Либо визуальный ярлык трех задач CRM (руки/голова/связки).
Минимум текста (заголовок наносит дизайнер). Формат — горизонтальный баннер блога. Стиль —
спокойный B2B, акцент `#7D4CCF`. Собирается по `make-cover`.

## 8. Внутренние визуалы
1. **Схема трех типов CRM** (руки/голова/связки) — после блока «Три типа CRM по задаче». ✅ готов вектор: `assets/crm-types.svg`.
2. **Схема «клиент проходит через отделы»** — в блоке «Коллаборационная CRM». Отрисовать дизайнеру.
3. **Схема-диагностика «симптом → тип CRM»** — в блоке «Как понять, какой тип нужен». Отрисовать дизайнеру.
4. (вспом., опц.) **Мини-схема «три независимые оси»** — в блоке «Другие оси». Можно оставить только текст, если перегруз.

## 9. Схемы
- `crm-types.svg` — три карточки: иконка + ярлык (руки/голова/связки) + тип + задача. Сделана.
- «клиент через отделы» — линейный поток: Продажи → Внедрение → Доставка → Поддержка, на стыках — маркер «теряется контекст». Вектор.
- «симптом → тип» — 4 ветки: «теряются заявки» → операционная; «данные есть, выводов нет» → аналитическая; «клиент теряется между отделами» → коллаборационная; «болит все» → комбинированная. Вектор.

## 10. Таблицы
Сравнительная таблица типов CRM уже сверстана в тексте (тип / задача / кому / признак /
примеры). Дизайнерского оформления не требует — оставить как HTML-таблицу (лучше для AEO и
нейровыдачи). Дублировать картинкой нельзя.

## 11. Скриншоты
Реальный скриншот CRM-доски Kaiten — **опционально** и только реальный (не выдумывать
интерфейс). Уместен рядом с мостиком про CRM-доску, но не обязателен: статья не продуктовая.
Если берем — из реального продукта, конфиденциальное заблюрить, подпись с источником.

## 12. Промпты для генерации
Только обложка (концептуальная, без текста) и — по решению редактора — один мем «в тему».
Схемы не генерируем растром: текст в них должен быть четким, отдаем в вектор. Финальные
промпты — в `12_visual_assets.md` §7.

## 13. Ограничения дизайн-системы
- Поверхности: белый `#ffffff`, светло-серые секции `#f5f5f5`; карточки — белые, граница `#e0e0e0`, радиус 16px.
- Единственный акцент — фиолетовый `#7D4CCF`; мягкая подложка `#EFE9F9`. Другие цвета — только для смысловой кодировки, дозированно.
- Текст: `#2D2D2D` основной, `#757575` вторичный. Шрифт Inter, заголовки SemiBold.
- Тон: спокойно, системно, без визуального шума. Никаких стоков и случайных мемов.

## 14. Что отдать дизайнеру
- отрисовать в вектор 2 схемы: «клиент через отделы» и «симптом → тип»;
- (опц.) мини-схему «три оси»;
- довести `crm-types.svg` при необходимости (проверить переносы, отступы);
- собрать обложку по `make-cover` (нанести заголовок);
- (если решим) оформить 1 мем «в тему» в рамках дизайн-системы;
- (если решим) вставить реальный скриншот CRM-доски Kaiten с подписью-источником.

## 15. Что проверить перед публикацией
- соответствие дизайн-системе (цвета, радиусы, Inter, один акцент);
- читаемость подписей на всех ширинах; текст в схемах — четкий, без обрезки;
- в схемах и на обложке нет выдуманного интерфейса продукта;
- alt-тексты проставлены (см. `12_visual_assets.md` §8);
- все пометки `[ВИЗУАЛ: …]` в тексте заменены на реальные изображения или сняты;
- мем — только если объясняет мысль и согласован редактором (не для разбавления).

## Развилка по мему (решение редактора)
Редактор просил «через интересное + мемы, не перебарщивать». Основную «интересность» несет
текст (рамка руки/голова/связки, сцены боли, врезка «интересный факт»). Мем-картинка —
максимум один, строго «в тему» (хаос ведения клиентов до CRM), в дизайн-системе. Рекомендация
визпродюсера: по умолчанию **без мема** (спокойный B2B-тон), но если редактор хочет — один,
аккуратный. Решение — на STOP 5.
